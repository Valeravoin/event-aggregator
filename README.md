# EventAggregator — бэкенд‑агрегатор событий

Агрегатор событий на стеке **FastAPI + SQLAlchemy + PostgreSQL**. Проект собирает события из разных источников, хранит их в единой базе, обеспечивает идемпотентную синхронизацию и отдаёт через REST API с пагинацией.

## 🚀 Быстрый старт

## Требования

- Python 3.10+
- PostgreSQL (локальный сервер)
- Локальная установка зависимостей (через `venv`)

> 💡 **Важно:** Перед запуском нужно вручную создать базу данных `event_aggregator` в PostgreSQL. Скрипты проекта не создают саму БД, только таблицы внутри неё.

## Клонирование и настройка

```bash
git clone <ССЫЛКА_НА_ТВОЙ_РЕПОЗИТОРИЙ>
cd event-aggregator
```

## Создание виртуального окружения и установка зависимостей

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### Настройка переменных окружения

Скопируй шаблон в рабочий файл:
```bash
cp .env.example .env
```

Открой файл .env и заполни переменные. Не используй кавычки, если в примере их нет.
```basch
DATABASE_URL=postgresql+psycopg2://postgres:ТВОЙ_ПАРОЛЬ@localhost:5432/event_aggregator
EVENTS_PROVIDER_BASE_URL=https://events-provider.dev-2.python-labs.ru
EVENTS_PROVIDER_API_KEY=твой_api_ключ

```

### Применение миграций базы данных

Так как проект использует Alembic, нужно применить миграции, чтобы создать таблицы в базе:
```bash
alembic upgrade head
```

### Запуск сервера

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```
После запуска открой в браузере http://localhost:8000/docs — должна открыться Swagger-документация.

### 🌐 Доступные эндпоинты

Метод|Путь|Описание и важные нюансы
GET|/api/health|Проверка статуса сервиса и соединения с БД. Возвращает { "status": "ok", "database": "connected" }.
GET|/api/events|Список событий с пагинацией и фильтрацией. Параметры: page (по умолчанию 1), page_size (1–100), date_from (ISO8601). Пример: /api/events?page=1&page_size=20&date_from=2026-11-01.
GET|/api/events/{event_id}|Детали конкретного события по UUID. Возвращает полную модель события.
GET|/api/events/{event_id}/seats|Свободные места для события. Возвращает available_seats и total_seats. Важно: может возвращать 403, если нет прав или событие не опубликовано.
POST|/api/sync/trigger|Ручной запуск синхронизации с внешним провайдером. Вызывает run_sync(db). Возвращает статус успеха/ошибки и количество обработанных записей.
POST|/api/tickets|Регистрация билета (создание регистрации). Принимает JSON: { "event_id": "...", "user_name": "...", "email": "..." }. Проверяет наличие мест и статус события.
DELETE|/api/tickets/{ticket_id}|Отмена регистрации билета. Возвращает подтверждение удаления или ошибку, если билет уже использован.
GET|/debug/stats|Отладочная статистика: общее число событий, число синхронизаций, статусы последних запусков. Доступ только в dev-режиме.
GET|/docs|Swagger UI (интерактивная документация API). Здесь можно протестировать все эндпоинты.

### 🧠 Архитектура и ключевые решения

- **Идемпотентная синхронизация**: upsert по UUID гарантирует отсутствие дублей при повторных запусках.
- **Фоновая синхронизация**: APScheduler с интервалом 24 часа балансирует актуальность и нагрузку.
- **Пагинация**: отдельные COUNT‑запросы, валидация `page_size` (1–100).
- **Безопасность сессий БД**: контекст `yield` гарантирует закрытие сессии даже при исключениях.
- **Идентификаторы**: UUID вместо автоинкремента — безопасно в URL и удобно для распределённых систем.
- **Управление секретами**: все ключи и URL вынесены в `.env`, файл исключён из коммитов через `.gitignore`.
- **Защита от параллелизма**: блокировка в БД предотвращает одновременные запуски синхронизации.
- **Логирование с контекстом**: каждый запрос и ошибка содержат `event_id`, `ticket_id` и источник проблемы.
- **Контроль качества кода**: CI (GitHub Actions) требует прохождения ruff/isort перед деплоем.
- **Валидация входа**: Pydantic‑схемы обеспечивают строгую проверку JSON до бизнес‑логики.


### 📦 Зависимости

Основные пакеты в `requirements.txt`:
- `fastapi`, `uvicorn` — веб‑фреймворк и сервер.
- `sqlalchemy`, `psycopg2-binary` — ORM и драйвер PostgreSQL.
- `httpx` — HTTP‑клиент для внешних API.
- `apscheduler` — фоновые задачи и расписание.
- `python-dotenv` — работа с `.env`.
- `pydantic` — валидация входных данных.
- `pytest`, `ruff`, `isort` — тестирование и контроль качества кода.
